# 架构整改快速上手指南

> **重要**: 本次架构整改涉及Backend、AI-Service、Frontend三个服务，请认真阅读本文档。

## 🚀 快速开始

### 1. 核心变更概览

#### 🔴 重要变更
- **API路径统一**: 所有AI功能接口统一为 `/api/v1/ai/*`
- **接口调用链路**: Frontend → Backend → AI-Service (Backend作为API Gateway)
- **熔断和降级**: 集成Resilience4j，AI服务不可用时自动降级

#### 🟢 新增功能
- **环境感知推荐**: AI推荐基于DEV/STAGING/PROD环境自动调整
- **版本感知推荐**: 大版本升级、紧急修复自动提升优先级
- **新UI页面**: 工作台首页、批量生成、策略推荐

## 🔧 配置变更

### Backend (application.yml)

```yaml
# 新增AI-Service配置
services:
  ai-service:
    url: ${AI_SERVICE_URL:http://localhost:8000}
    timeout:
      connect: 5000
      read: 30000
    base-path: /api/v1/ai

# 新增Resilience4j配置
resilience4j:
  circuitbreaker:
    instances:
      aiService:
        failure-rate-threshold: 50
        wait-duration-in-open-state: 30s
  retry:
    instances:
      aiService:
        max-attempts: 3
        wait-duration: 1s
```

### AI-Service (.env)

## 💡 关键概念

### 1. API Gateway模式

**调整前**:
```
Frontend ─┬─→ Backend (业务)
          └─→ AI-Service (AI) ❌
```

**调整后**:
```
Frontend ──→ Backend ──→ AI-Service
              (Gateway)
              ├─ Circuit Breaker
              ├─ Retry
              └─ Fallback
```

**好处**:
- ✅ 统一入口，前端只需调用Backend
- ✅ 自动熔断和降级，提升可用性
- ✅ 集中监控和日志

### 2. 环境感知推荐

AI推荐会根据部署环境自动调整策略：

| 环境 | 推荐范围 | 优先级调整 | 说明 |
|------|---------|-----------|------|
| **PROD** | FULL | +2 | 生产环境，全量回归 |
| **STAGING** | CORE | +0 | 预发环境，核心回归 |
| **DEV** | SMOKE | +0 | 开发环境，冒烟测试 |

**示例请求**:
```json
{
  "task_id": "task-001",
  "environment_id": "env-prod",  // ← 新增
  "version_id": "version-2.0.0", // ← 新增
  "context": {
    "code_change": {
      "changed_files_count": 20
    }
  }
}
```

**响应**:
```json
{
  "recommendation": {
    "test_scope": "FULL",        // PROD → FULL
    "priority": 10,              // 原本8 + 2
    "reasoning": [
      "环境为生产环境(PROD)，推荐全量回归测试",
      "版本2.0.0为大版本升级，建议全面回归测试"
    ]
  },
  "risk_assessment": {
    "risk_level": "HIGH"         // PROD风险提升
  }
}
```

### 3. 熔断和降级

当AI-Service不可用时：

**Backend自动降级**:
```java
// AIServiceClient会捕获异常并返回友好错误
{
  "success": false,
  "message": "AI服务暂时不可用，请稍后重试或使用手动创建功能",
  "generated_cases": null
}
```

**Frontend友好提示**:
```typescript
try {
  const result = await aiService.generateTestCases(request);
} catch (error) {
  message.error('AI服务暂时不可用，请稍后重试');
  // 引导用户使用手动创建功能
}
```

## ❓ 常见问题

### Q1: 旧代码会报错吗？

**A**: 是的，如果Frontend或其他服务直接调用了旧接口（如 `/api/v1/test-cases/generate`），会收到 **404 Not Found** 错误。

**解决方案**:
- 立即更新API调用路径到 `/api/v1/ai/*`
- 或者使用Frontend的 `aiService.ts`，已经封装好所有接口

### Q2: AI-Service宕机会影响系统吗？

**A**: 不会影响核心功能。Backend实现了自动降级：
- ✅ 系统正常运行
- ✅ 返回友好错误提示
- ✅ 可以使用手动创建功能

### Q3: 如何监控熔断器状态？

**A**: 访问 Spring Boot Actuator端点：
```bash
# 查看熔断器指标
curl http://localhost:8080/actuator/metrics/resilience4j.circuitbreaker.state
curl http://localhost:8080/actuator/metrics/resilience4j.circuitbreaker.calls

# 查看所有指标
curl http://localhost:8080/actuator/metrics
```

### Q4: 测试环境如何配置？

**A**: 使用 `application-test.yml`:
```yaml
services:
  ai-service:
    url: http://ai-service-test:8000  # 测试环境AI服务
```

或使用环境变量:
```bash
export AI_SERVICE_URL=http://ai-service-test:8000
mvn test
```

### Q5: 新增的3个UI页面在哪里？

**A**:
1. **工作台首页**: http://localhost:3000/ (左侧菜单 "工作台")
2. **批量生成**: http://localhost:3000/test-cases/batch-generate (测试用例 → 批量生成)
3. **策略推荐**: http://localhost:3000/recommendation/strategy (智能推荐 → 策略推荐)

## 🚨 注意事项

### ⚠️ Breaking Changes

1. **API路径变更** - 所有AI接口路径已统一，旧路径已删除
2. **推荐接口增强** - `environment_id` 和 `version_id` 为新增可选参数
3. **响应格式** - 部分字段名称调整（保持兼容）

### ⚡ 性能影响

- **新增网络跳转**: Frontend → Backend → AI-Service (多一跳)
- **预期延迟**: +10-50ms (可忽略)
- **稳定性提升**: 自动重试、熔断、降级

### 🔒 安全增强

- Backend统一鉴权，AI-Service不再对外暴露
- 集中日志审计
- 降低API滥用风险
