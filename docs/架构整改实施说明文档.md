## 项目概述

### 背景

SynapseTest是一个AI驱动的测试任务管理系统，包含三个核心服务：
- **Backend**: Spring Boot后端服务，提供业务API
- **AI-Service**: FastAPI AI服务，提供AI推荐和生成能力
- **Frontend**: React前端应用，提供用户交互界面

### 整改范围

本次架构整改覆盖了以下4个主要问题域：
1. **接口调用架构优化** - 消除重复接口，统一调用路径
2. **测试用例完整性** - 补充集成测试
3. **AI-Service功能扩展** - 增强环境和版本感知能力
4. **Frontend功能完善** - 补充缺失的UI页面

## 架构调整详情

### 整体架构变化

#### 调整前架构
```
Frontend ──┬──→ Backend (业务API)
           └──→ AI-Service (AI API) ❌ 直接调用
```

#### 调整后架构
```
Frontend ──→ Backend ──→ AI-Service
              (API Gateway)
              ├─ Circuit Breaker
              ├─ Retry Mechanism
              └─ Fallback Strategy
```

## 技术实现细节

### 1. Backend - AIServiceClient

#### 核心特性

**熔断器 (Circuit Breaker)**:
```yaml
resilience4j:
  circuitbreaker:
    instances:
      aiService:
        failure-rate-threshold: 50          # 失败率阈值50%
        wait-duration-in-open-state: 30s    # 熔断器打开后等待30秒
        sliding-window-size: 10             # 滑动窗口10次请求
        minimum-number-of-calls: 5          # 最少5次调用后开始统计
```

**重试机制 (Retry)**:
```yaml
resilience4j:
  retry:
    instances:
      aiService:
        max-attempts: 3                     # 最多重试3次
        wait-duration: 1s                   # 重试间隔1秒
        retry-exceptions:
          - java.net.SocketTimeoutException
          - org.springframework.web.client.HttpServerErrorException
```

**降级策略 (Fallback)**:
```java
@CircuitBreaker(name = "aiService", fallbackMethod = "generateTestCasesFallback")
@Retry(name = "aiService")
public AITestCaseGenerationResponse generateTestCases(AITestCaseGenerationRequest request) {
    // 调用AI-Service
}

private AITestCaseGenerationResponse generateTestCasesFallback(
        AITestCaseGenerationRequest request, Exception e) {
    // 返回友好错误信息
    AITestCaseGenerationResponse response = new AITestCaseGenerationResponse();
    response.setSuccess(false);
    response.setMessage("AI服务暂时不可用，请稍后重试或使用手动创建功能");
    return response;
}
```

#### 环境信息获取

```python
def get_environment(self, environment_id: str) -> Optional[Dict[str, Any]]:
    """从Backend获取环境信息"""
    url = f"{self.backend_url}/api/v1/test-environments/{environment_id}"

    try:
        response = requests.get(url, timeout=self.timeout)
        response.raise_for_status()

        result = response.json()
        if result.get('success') and result.get('data'):
            return result['data']
    except Exception as e:
        logger.warning(f"Failed to fetch environment {environment_id}: {e}")
        return None
```

#### 推荐策略调整

```python
def _adjust_recommendation_by_environment(self, recommendation, environment_info):
    """基于环境调整推荐"""
    env_name = environment_info.get('name', '').upper()

    if env_name == 'PROD':
        recommendation['test_scope'] = 'FULL'
        recommendation['priority'] = min(10, recommendation.get('priority', 5) + 2)
        recommendation['reasoning'].append(
            f"环境为生产环境({env_name})，推荐全量回归测试以确保稳定性"
        )
    elif env_name == 'STAGING':
        if recommendation.get('test_scope') == 'SMOKE':
            recommendation['test_scope'] = 'CORE'
        recommendation['reasoning'].append(
            f"环境为预发环境({env_name})，推荐核心回归测试"
        )

    return recommendation
```

## 注意事项

### 开发注意事项

1. **接口调用路径变更**
   - ⚠️ 不要再使用旧的接口路径 (如 `/api/v1/test-cases/generate`)
   - ✅ 统一使用新的接口路径 (如 `/api/v1/ai/testcase/generate`)

2. **降级策略**
   - AI服务不可用时，系统应能正常运行
   - 前端需提示用户"AI服务暂时不可用"
   - 后端应记录降级日志，便于监控告警

3. **超时配置**
   - AI生成可能需要较长时间，建议设置30秒读取超时
   - 批量生成建议设置60秒超时

4. **错误处理**
   - 所有AI接口调用都应该有try-catch
   - 失败时应提供友好的用户提示

### 运维注意事项

1. **熔断器监控**
   - 监控熔断器状态 (CLOSED/OPEN/HALF_OPEN)
   - 熔断器打开时应触发告警
   - 查看Resilience4j metrics: `/actuator/metrics/resilience4j.circuitbreaker.*`

2. **性能监控**
   - 监控AI-Service响应时间
   - 监控降级发生频率
   - 设置告警阈值 (如响应时间>10s, 降级率>10%)

3. **日志收集**
   - Backend和AI-Service都会记录详细请求日志
   - 日志格式: `[REQUEST/RESPONSE] {method} {path} - Status: {status}, Time: {time}`
   - 建议使用ELK或类似工具集中收集日志

4. **容量规划**
   - AI-Service建议部署多实例 (至少2个)
   - Backend通过Ribbon/LoadBalancer实现负载均衡
   - 预留足够的GPU资源用于AI推理

### 测试注意事项

1. **集成测试**
   - 运行测试前确保test profile配置正确
   - 使用MockRestServiceServer模拟AI-Service响应
   - 不要在测试中真实调用AI-Service

2. **端到端测试**
   - 在测试环境启动完整服务栈
   - 验证Frontend → Backend → AI-Service完整链路
   - 测试熔断和降级场景
